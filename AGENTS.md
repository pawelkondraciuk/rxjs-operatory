## Zacznij tutaj

Polska prezentacja „RxJS — Operatory, które znasz, ale bałeś się zagadać”, oparta na Reveal.js. Najpierw przeczytaj ten dokument i README.md (treści, kolejność, speaker notes). Czytaj kod potrzebny do konkretnej zmiany. Zachowuj język polski, identyfikatory slajdów i semantykę RxJS 7.8.2. Po zmianie treści aktualizuj README; po zmianie animacji, architektury lub sterowania także ten plik.

Całość: 35 bazowych slajdów HTML, 42 po rozwinięciu wariantów, 29 animowanych. MAIN: 39 slajdów (26 animowanych), EXTRAS: 3 slajdy. 04a-dwa-tory, -2 i -3 to warianty torów wykonania: cold (trzy pola widoku user$, trzy requesty, trzy complete), share() + HTTP (HTTP GET → share() → pola A/B/C, jeden request) i share() + interval (odpowiednik Subject + interval: ostatni odbiorca odłącza źródło). Otwarcie do slajdu tytułowego pozostaje niezmienione w HTML (bez slajdów ReactiveX i legendy animacji); czas 30–35 minut obejmuje wyłącznie część właściwą. Map + concatAll (08-map-strumienie) jest kluczową częścią MAIN bezpośrednio przed concatMap; cztery *Map (09–12) stoją obok siebie, a jedyny distinctUntilChanged (11a-distinct-switchmap) jest po pokazach switchMap na żywo i debounceTime + switchMap; bezpośrednio po nim ta sama wyszukiwarka z catchError wewnątrz switchMap (11b-catcherror-search). Notatki są wspólne dla wariantów sekcji i mają opisane części dla wariantów, z wyjątkiem HTTP (05-zrodla-2), cold (04a-dwa-tory), share() + HTTP (04a-dwa-tory-2), share() + interval (04a-dwa-tory-3), Subject — ręczna emisja (05-zrodla-5), Subject (05-zrodla-3), Subject + interval (05-zrodla-4), pary share/shareReplay z późnym odbiorcą (20-sharereplay, -2), shareReplay(1) na interval (20a-sharereplay-interval), shareReplay z refCount: true na interval (20b-sharereplay-refcount), catchError na zewnątrz, distinctUntilChanged przed switchMap, catchError w wyszukiwarce (11b-catcherror-search), trzech EXTRAS, map + concatAll (08) oraz czterech strategii 09–12, które mają własne notatki per checkpoint. Scena katalogowa 01-tytul nie jest podpięta do HTML.

EXTRAS zawiera kolejno x02-combinelatest-withlatestfrom (combineLatest z dwoma źródłami i lokalną pamięcią ostatnich wartości), x03-retry-backoff (retry z backoff 1/2/4 s) i x04-defer (from(loadUser()) vs defer(() => loadUser()) w dwóch fazach jednego diagramu), zaraz po „Pytania?”. Kolejność wprowadzenia: HTTP 05-zrodla-2 → kod httpGet 05b-http-kod → Cold 04a-dwa-tory (jedna definicja, trzy wykonania, trzy complete) → interval 05-zrodla (cold: A i B mają osobne wykonania) → Subject — ręczna emisja 05-zrodla-5 (next, późny subskrybent bez historii, complete) → Subject + HTTP 05-zrodla-3 (te same pola widoku co Cold) → Subject + interval 05-zrodla-4 → 02-znane-operatory → 04-operator (HTTP GET + map na obiekcie User) → kod myMap 04b-map-kod → 03-a-share. ## Stos i uruchomienie

JavaScript, HTML i CSS, bez frameworka. Reveal.js ^6.0.2, Vite ^8.3.3, qrcode ^1.5.4. RxJS i Angular są tematami przykładów, nie zależnościami wykonawczymi: nie wykonujemy prawdziwych requestów ani potoków. QR są gotowymi SVG w public/. package.json ma type: commonjs; kod przeglądarki używa ESM przez Vite, konfiguracja .mjs, testy .cjs.

Uruchomienie: npm ci, npm run dev. Weryfikacja: npm test, npm run build. Podgląd buildu: npm run preview. Vite isPreview ustawia /rxjs-operatory/ także w preview, zgodnie z prefiksem zasobów buildu; dev zachowuje /. Adres/port odczytaj z komunikatu serwera; base to /rxjs-operatory/. Testy używają node --experimental-vm-modules --test tests/*.test.cjs. Prototypy v2: /work/framework-prototypes.html (serwer developerski); Kontroler playback.controller: 'stages' działa w przebudowanym wprowadzeniu (04, 04a-2, 04a-3, pięć wariantów 05, oba 20). Rodzina flatteningu 08–13 zachowuje dotychczasowe fragmenty i sterowanie.

## Kontrakt sceny

Scena ma id, title, tekst code, opcjonalne codeFrames:[{at,code}] (czas ilustracji; snapshot wybiera ostatni osiągnięty wpis, a wcześniej scene.code), duration (czas modelu), rows, captions, metrics oraz opcjonalnie graph i playback. Wiersz: {label, events, spans, completeAt?}. Zdarzenie: {at,value,color,kind}. Przedział: {start,end,label,color,kind,duration?}; rodzaje work, queue, cancel, subscription, state, window, error. Brak completeAt nie oznacza końca przy ostatniej wartości. duration przedziału zachowuje potencjalny czas pracy po anulowaniu, żeby pasek nie dochodził do 100%. graph.illustratedWork:true (prototypy v2 i migrowana rodzina flatteningu) liczy pasek w czasie ilustracji od subskrypcji do complete/unsubscribe/błędu HTTP, więc nie staje podczas przelotu wartości; wiersz dostaje complete razem z pełnym paskiem. Bez flagi zachowanie jest dotychczasowe.

Katalog ma późniejsze revise(...) i variants nadpisujące wcześniejsze definicje. configureReferences() działa przed checkpointami katalogu. configureScene() działa po wybraniu wariantu w prepareSlides(): tam ustawiaj konfigurację zależną od wariantu.

graph jest obiektem albo czystą funkcją sceny. Ma nodes, edges, trays oraz opcjonalne layout/width/height, panels, queue, timeline, schedule, transforms, activities, tokens.

- Węzły: stabilne id, label, ri (wiersz), work/inner/timer, ready, born lub createdBy:{edge,value}. Cały graf rezerwuje układ przed odtwarzaniem. ready:true pokazuje niepołączonych uczestników, createdBy ujawnia inner dopiero po dotarciu wejścia do projekcji.
- Krawędzie: from, to, events, opcjonalnie logicalStart, logicalEnd:{at,kind}, gateWork, internal, points. internal zachowuje semantykę subskrypcji w planie, ale nie rysuje kabla ani tokenów wewnętrznej krawędzi. Subscribe idzie od odbiorcy ku źródłu; next/complete/error ku odbiorcy.
